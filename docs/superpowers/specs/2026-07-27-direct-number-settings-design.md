# GokuGoku 数字设置与上班时间修复设计

## 目标

- 体重、每次喝水量和催水间隔均使用可直接键盘输入的数字框。
- 用户界面中把“杯容量”和“每杯容量”统一改为“每次喝水量”。
- 完全移除自动催水间隔及 30 / 45 / 60 / 90 分钟固定选项。
- 修复用户操作上班时间下拉框时，选择偶尔被状态刷新打断或还原的问题。

## 交互设计

主设置页和首次设置页继续使用原有单列表单，不改变整体布局：

- 体重输入范围保持 `30–300kg`，步长 `0.1kg`。
- 每次喝水量输入范围保持 `50–1000ml`，步长 `10ml`。
- 催水间隔改为数字输入，范围 `1–1440` 分钟，步长 `1` 分钟。
- 首次设置中的催水间隔默认显示当前保存值；新用户默认值为 `45` 分钟。
- 主设置页中的催水间隔在输入完成并触发 `change` 时保存，行为与当前选择固定间隔一致。
- 上班开始和结束时间继续使用现有下拉框及现有可选时段。

输入无效时不写入设置，并在设置区显示明确的范围提示。首次设置只有在体重、每次喝水量、催水间隔和免打扰时段均有效时才可完成。

## 数据与兼容

- 内部继续使用 `cupMl` 和 `intervalMin` 字段，避免改写历史饮水记录或提升数据库版本。
- 默认 `intervalMode` 改为 `manual`。读取旧数据时保留已保存的 `intervalMin`，并把旧的 `auto` 模式归一化为 `manual`；之后不再自动重算间隔。
- 记录一次喝水时仍把当前 `cupMl` 加入当日累计量，因此文案修改不会改变现有计算规则。
- `intervalMin` 的服务端校验从固定枚举改为 `1–1440` 的整数范围，前端限制不能替代服务端校验。

## 上班时间根因与修复

主进程每秒推送一次状态，渲染函数也每秒把保存的 `workStart` 和 `workEnd` 回写到两个下拉框。Windows 原生下拉框打开期间，这次回写可能打断尚未提交的选择，表现为偶尔无法设定。

渲染时仅在对应下拉框未获得焦点时同步服务端值。用户完成选择并触发 `change` 后，继续调用现有设置接口保存；主进程返回的新状态再正常同步。这样既消除操作中的竞争，也保留外部状态更新后的界面一致性。

## 代码范围

- `ui/index.html`：替换催水间隔控件，补充首次设置输入，统一可见文案。
- `ui/index.js`：移除自动和固定间隔按钮，绑定数字输入，增加校验，并避免回写正在操作的上班时间控件。
- `main.js`：接受 `1–1440` 的整数间隔，移除自动重算路径。
- `lib/data.js`：新数据默认手动间隔，旧数据加载时归一化模式。
- `lib/hydration.js`：集中校验资料和间隔输入，并更新错误文案。
- `test/*.test.js`：覆盖数字范围、旧自动模式兼容、自动控件移除、文案以及上班时间焦点保护。
- `README.md` 与使用说明：同步用户可见术语和手动间隔说明。

## 验证

1. 先增加会失败的测试，分别证明旧代码仍限制固定间隔、仍显示自动控件、仍使用旧文案且会回写聚焦中的上班时间控件。
2. 完成最小实现后运行 `npm test`，确保所有饮水、数据迁移和调度测试通过。
3. 启动 Electron 应用，检查首次设置和主设置可直接输入数字，边界错误可见且无效值不保存。
4. 保持上班时间下拉框打开超过一次一秒刷新周期，确认选择不会被还原；完成选择后重启应用，确认值已持久化。
5. 确认修改每次喝水量后，新打卡按新数值累计，既有当日累计量不被改写。
